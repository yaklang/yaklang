# ISO 8583 card-originated carrier

ISO 8583 is the interchange format behind card payment traffic. `pcaputil`
implements it as a native TCP profile: no YAML rule, no port guess and no
configuration switch. Registering a protocol message callback is enough.

## Carrier

Both public sample captures carry one message per TCP segment after a two-byte
**little-endian** length prefix. The prefix counts the message body only, so the
admitted frame is `2 + declared` bytes. A big-endian prefix is also probed; the
byte order is decided once per flow and recorded, never re-guessed per message.

Admission requires the whole envelope to validate: a published MTI, the primary
bitmap, and (when bit 1 is set) the secondary bitmap. A weak "four digits and
some hex" prefix is not enough — the first message must decode completely before
the flow is claimed. Detection runs after every strong signature, so TLS records
or HTTP/2 frames that open with bytes resembling a length cannot take the flow.

## Field model

The element table is the published ISO 8583:1987 definition, with the 1993/2003
revision applied where both carriers of the same exchange pin it: version digit
`1` (and `2`) widens element 39 from two alphanumeric characters to three
numeric digits.

| Aspect | Behaviour |
|---|---|
| MTI | Four dimensions decoded and labelled: version, message class, message function, message origin |
| Bitmap | Primary plus optional secondary bitmap; element 65 is not decoded |
| Encoding | ASCII and packed BCD carriers; the same exchange decodes identically from both |
| Length kinds | Fixed, `LLVAR` and `LLLVAR` with the published per-element maximum length |
| Binary elements | Returned as bytes, so the ASCII hexadecimal carrier and the packed carrier agree |
| Odd-width numerics | The packed carrier keeps a leading pad nibble; it is dropped so an odd-width element matches its ASCII form |
| Reserved elements | Kept at their declared width and left opaque; nothing is guessed into subfields |
| Sensitive elements | PAN, track and PIN elements carry a `Sensitive` marker and are returned unmodified |

Bounded work: the element count is checked against the collection budget before
any allocation, and the declared length of every element is validated against
the published maximum and the remaining message bytes.

## Refusals

The profile never trims a message to make it fit.

| Situation | Result |
|---|---|
| Declared length exceeds the configured message budget | `limited` |
| MTI outside the published version/class/function/origin dimensions | `malformed` |
| Non-hexadecimal ASCII bitmap, non-BCD packed MTI | `malformed` |
| An element declares more than its published maximum | `malformed` |
| Bytes remain outside the declared elements | `malformed` |
| A split first message | held as `incomplete` until the declared length arrives |

Both sealed captures end with one short message whose MTI is outside the
published dimensions (`0a00` and `00f8`). Those stay explicit refusals; they are
not decoded as ISO 8583.

## Scope

This profile decodes the carrier and the data elements. It does **not**
associate requests with responses, verify a message authentication code or a PIN
block, or make any issuer-policy, cardholder-authentication or trust claim. PAN,
track and PIN data are evidence: masking them is a caller policy. The same
carrier boundary is recorded in
[`PROFILES.md`](PROFILES.md) and `protocol_registry.go`.

## Sealed evidence

`common/bin-parser/testdata/corpus-batches/validation-iso8583-public-6a1af0a7c22.zip`
holds both public Wireshark ISO 8583-1 captures, their independent answer
documents and the verifier that produced them (`tools/verify.py` — a standalone
pcapng/TCP/field decoder that never imports the Go parser). The answers cover
every admitted message: MTI dimensions, encoding, secondary-bitmap presence,
element order and per-element length and value.

Regenerate the answers with:

```sh
cd <this batch>            # or the exported workspace copy
python3 tools/verify.py --digest
python3 tools/verify.py > /tmp/answers.json
```

The Go-side regression is `TestISO8583SealedReplay` in
`protocol_iso8583_test.go`, alongside unit tests for the envelope, the framing
boundary and the version-dependent response code.
