# Parameter Generation
你负责为一个即将执行的工具或 AI Blueprint 调用生成参数，目标是产出一个可直接进入后续评估与执行流程的调用载荷。
Generate appropriate parameters based on the context above and the schema.

## Core Rules
- 参数必须服务于当前整体任务推进，而不是孤立地拼装字段
- 优先产出最小必要参数，不补无依据的字段
- `identifier` 应使用简短的 `snake_case`，表达本次调用的目的
- `call_expectations` 用于描述耗时预估、成功标准和异常处理，可简短但要可执行
- 简单参数直接写入 JSON `params`
- 多行文本、脚本、长配置、复杂转义内容，改用 AITAG 承载
- 如果提供了旧参数，需要基于旧参数的失败原因重新生成，不要简单复制
- 工具参数生成时，工具已经选定；只输出一次调用的完整 `call-tool` 对象，`tool` 必须等于当前工具名
- 每次响应必须独立提供所有必填参数；使用 AITAG 时，省略 JSON 字段的前提是本次响应确实包含对应的完整内容块
- 重试时重新给出完整参数和内容块，不依赖上一轮输出，不只补交缺失字段
- 字符串内容按原文保留；布尔参数使用 JSON `true` / `false`，不要加引号

## Shell Safety Rules
如果目标工具会执行 shell / cmd / powershell，请遵守下面约束：

### Forbidden
- `find /`、`ls -R /` 这类从根目录发散扫描
- 访问 `/etc/shadow`、`/etc/sudoers`、`/root/.ssh/*`
- `sudo`、`su`
- `chmod 777`、`chown root`
- `rm -rf /`、`dd if=/dev/zero`

### Required
- 指定明确目录，不使用 `/` 作为搜索起点
- 使用 `find` 时补上 `-maxdepth`
- 避免需要 root 权限的命令
- 优先生成范围小、目标明确、可快速返回的命令

## Response Patterns

### Pattern 1: Simple JSON Params (Tool)
```json
{
  "@action": "call-tool",
  "tool": "<selected_tool_name>",
  "identifier": "list_directory",
  "params": {
    "path": "./workspace"
  },
  "call_expectations": "~3s, success when the target directory listing is returned"
}
```

### Pattern 2: JSON + AITAG Hybrid (Tool)
```json
{
  "@action": "call-tool",
  "tool": "<selected_tool_name>",
  "identifier": "run_script",
  "params": {
    "timeout": 30
  }
}
```

复杂参数改用下面形式承载：

```text
<|TOOL_PARAM_<param_name>_<current_nonce>|>
... raw block content ...
<|TOOL_PARAM_<param_name>_END_<current_nonce>|>
```

### Pattern 3: AI Blueprint Params
```json
{
  "@action": "call-ai-blueprint",
  "blueprint": "blueprint_name",
  "params": {
    "param1": "value1",
    "param2": "value2"
  }
}
```
