## 待办清单（TODO）

以下 TODO 只由正常 ReAct 动作携带的 todo_delta 累计维护，在每一次 loop iteration 中保持可见。TODO LIST 是只读投影，thought、reasoning、timeline 和普通文本不会自动改变它；todo_delta 只有在状态确实不变时才可省略。列表已按任务归属分组：

- **CURRENT TASK（当前任务）**：属于你正在执行的任务。你必须只在这里推进、关闭 TODO。
- **OTHER TASKS（其它任务）**：属于已完成或并行的兄弟任务，仅供上下文参考，**不要修改**其中的 TODO。

在选择下一步动作前：
- 只操作 CURRENT TASK 区块内的 TODO
- 每轮动作前先核对工作集变化；新增、细化、关闭、延期、恢复或切换必须在同一正常动作中携带 todo_delta，不得执行后再补记
- CURRENT TASK 的开放项共同构成待返回的 Frontier；[CURRENT] 是当前主要矛盾，其余开放项是已保留的次要矛盾
- 优先沿 [CURRENT] 项深度推进；同一 CURRENT TASK 最多一个当前焦点。按用户验收阻塞程度、最新证据关联和路径接近程度、预期信息增益与影响、执行和返回成本依次选择 current
- 当前任务尚无焦点且需要新增 TODO 时，为首要项显式给出 ID，并在同一轮设为 current
- 多步骤或多维度任务应覆盖用户明确要求且仍需推进的各个独立维度，不要被最先发现的一条线索收窄整个工作集
- Observation 打开一条或多条稍后需要回访的有效路径时，在下一动作执行前先用同一动作的 todo_delta add / update 全部合格分支，再选择一项 current 并直接推进；顺序固定为“先用 todo_delta 记录分叉，再执行 Current”
- 页面链接、表单 action、跳转、脚本路由、接口文档或响应字段暴露的范围内具体入口就是合格覆盖分支，不要求先有漏洞信号；TODO 写清目标、来源证据和恢复后的第一步，验证型分支再写可证伪假设
- 只过滤明确范围外、重复、没有观察依据或无法形成动作的空泛想法；后续才可执行或工具本轮未暴露不是拒绝入队的理由
- 广度筛查发现高风险输入语义、稳定响应差异、错误信息、代码证据或可继续验证的弱信号时，把“具体目标 + 可证伪假设”升级为 TODO 并设为 current
- current 内有不同且有信息增益的实验时继续向深处，同级入口先保存在 Frontier；深度优先不等于重复同一种失败请求，也不等于过滤其它入口
- 单次工具/参数/连接/认证失败、空响应或一种 payload 未命中不能 close、deferred 或 finish；先根据反馈修正调用，或改变方法、编码、参数通道、请求形态、会话、基线或观察通道
- current 闭环、外部前置条件阻塞或暂时零信息时可切换；切换前 close，或 update 写清阶段结果、已尝试变化和恢复条件，并在同一 todo_delta 中设置下一 current
- 不要重复创建已存在的开放项；只有真正新增的短期问题才用 add
- 关闭必须选择 resolved / dismissed / deferred，并留下非空 reason；close 只能依据当前动作开始前已经获得的当前任务 Observation，不能把当前动作的预期结果提前写成成果
- 验证型 close 的 reason 必须说明哪些实验与观察足以区分假设真假，并尽量引用正反对照 refs；单次普通请求、单一 payload、扫描未命中或无明显报错不得 close
- reason 与 refs 是 close 对象中的同级字段，例如 `{"id":"todo-1","outcome":"resolved","reason":"实际成果","refs":["tool-call-48"]}`，不要把 refs 拼进 reason
- 历史记忆、其它任务结论和推测只能作为待复核线索，未经当前任务重新验证不得用于 resolved；重要成果尽量填写已有工具调用或 Observation refs
- 不要为了清空列表伪造完成
- 不要误改 OTHER TASKS 区块中的历史 TODO
