# 任务 2：原生工具调用能力探测

状态：WIP。本任务从 `main` 独立开展；PR #5198 的 prompt、投影和 action 执行改动稍后再 rebase 到合并后的 `main`。

## 目标与边界

为实际 AI 目标提供可复用的工具调用能力判断，让现有 `aim.InvokeReAct` 脚本无需新增必填参数。此 PR 先建立独立的能力探测、缓存和测试；不在旧 ReAct 链路中强行开启新的 function-call 执行协议。PR #5198 rebase 后再把探测结果接到本轮 prompt/transaction 模式选择上。

本任务不修改双模式提示词、投影失败回退、纯文本结束与多 action 执行政策，也不把一次普通文本响应误判为模型不支持工具。

## 能力状态

- 区分用户意图（允许、禁用或强制）与目标能力（未知、支持、不支持）。不能用单个 `false` 同时表示未检测和不支持。
- 缓存按实际请求目标隔离，至少考虑 provider、endpoint、model、请求协议及影响路由的配置；缓存键不包含明文凭据。路由变化、配置变化或过期后重新判断。同一目标的并发首次请求共用一次探测。
- 优先使用可信的显式能力配置。未知时，首次使用前以无业务副作用的请求验证相同传输路径的 tools、tool call 响应与必要的回放格式。探测不写入会话 timeline、不调用真实 action，也不向用户流输出探测内容。
- 明确拒绝 tools 的响应可以判为不支持；有效 tool call 可以判为支持。模型在可选工具请求中只返回文本、网络故障、超时或限流，均不能判为不支持，应保留未知状态并采用兼容行为。
- 探测和缓存是选择提示词的输入，不代替真实请求的错误处理。即使缓存标记支持，服务端之后仍可能拒绝 tools。

## 兼容性与验收

1. 现有 `aim` 导出函数及脚本参数不变；显式禁用 function-call 的配置继续生效。探测失败不得污染会话、执行 action 或使正常文本路径失效。
2. 覆盖支持、不支持、不确定、瞬时错误、路由变更、并发首调和缓存失效。验证同一轮最终选用的 prompt 与 transaction 模式一致；模式选择不能发生在 prompt 已组装之后。
3. 首次探测可能增加请求、耗时和 token；记录这一开销，不宣称零成本。后续 AIM benchmark 分别衡量冷启动和缓存命中的体验。
4. PR 合并前提供探测请求/响应的脱敏诊断、决策来源和可复现测试；不以等待 CI 作为当前 WIP 阶段的工作阻塞。

## 与后续工作的接口

合并本 PR 后，PR #5198 rebase `main`，在其新 ReAct prompt/transaction 链路中消费能力结果。该集成应在每轮 prompt 组装前确定模式；本地投影失败的本轮纯文本回退由任务 1 负责。最终以仓库现有 AIM Yak benchmark 和代表性场景做对照，属于任务 3。
