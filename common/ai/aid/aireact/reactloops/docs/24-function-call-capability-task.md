# 任务 2：原生工具调用能力探测

状态：WIP。本任务从 `main` 独立开展；PR #5198 的 prompt、投影和 action 执行改动稍后再 rebase 到合并后的 `main`。

## 目标与边界

为实际 AI 目标提供可复用的工具调用能力判断，让现有 `aim.InvokeReAct` 脚本无需新增必填参数。首次执行 ReAct 任务、组装 prompt 之前，声明一个 `yak_probe_echo` 工具并要求模型用固定参数调用它。只收到有效的 echo tool call 才启用本轮原生模式；普通文本或暂时错误仍是“未知”，本轮走文本 action 路径。探测不会执行 echo 对应的业务动作，也不会写入任务 timeline。

本任务不修改双模式提示词、投影失败回退、纯文本结束与多 action 执行政策，也不把一次普通文本响应误判为模型不支持工具。

## 能力状态

- 区分用户意图（允许、禁用或强制）与目标能力（未知、支持、不支持）。不能用单个 `false` 同时表示未检测和不支持。
- 缓存隔离在一个 `Config` 内，按 service、model 和当前 callback tier 区分，避免不同会话的凭据和自定义 callback 误用同一结果。同一配置内并发首次请求共用一次探测；默认有效期 30 分钟，未知结果最多缓存 1 分钟。派生的新 `Config` 会重新探测。
- 显式禁用 function-call 时不探测；显式指定 ReAct loop 模式时保留调用方选择。默认模式通过当前任务使用的原始 AI callback 发探测请求，传递 `tools` 和 `tool_choice=auto`，绕开事件流与 checkpoint。
- 明确拒绝 tools 的响应可以判为不支持；有效 tool call 可以判为支持。模型在可选工具请求中只返回文本、网络故障、超时或限流，均不能判为不支持，应保留未知状态并采用兼容行为。
- 探测和缓存是选择提示词的输入，不代替真实请求的错误处理。即使缓存标记支持，服务端之后仍可能拒绝 tools。

## 兼容性与验收

1. 现有 `aim` 导出函数及脚本参数不变；显式禁用 function-call 的配置继续生效。探测失败不得污染会话、执行 action 或使正常文本路径失效。
2. 覆盖有效 echo、不支持、不确定、并发首调和显式关闭。模式选择发生在 prompt 组装之前；同一轮 prompt 与 transaction 读取同一个模式值。
3. 首次探测可能增加请求、耗时和 token；记录这一开销，不宣称零成本。后续 AIM benchmark 分别衡量冷启动和缓存命中的体验。
4. 探测日志记录能力结果或失败原因，不记录密钥与完整响应；保留可复现的定向测试。不以等待 CI 作为当前 WIP 阶段的工作阻塞。
