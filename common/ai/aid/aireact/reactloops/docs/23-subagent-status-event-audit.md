## 为什么显示“思考49秒”

本地Yakit源码的`chatStore.ts`会合并相邻、同NodeId的流。
`AIGroupStreamCard.tsx`以最后一条流的状态控制整组思考状态，并以首条token作为计时标识。
`ThoughtDuration.tsx`按浏览器墙钟计时，重新开始时保留原startedAt；它不使用服务端
`stream-finished.duration_ms`求和。

旧等待动作只有瞬时status，没有独立的可见动作流。16:08:20至16:09:09的49秒中，
包括约4秒等待、5秒父请求处理、13秒等待、27秒父请求处理。
相邻思考流跨过等待被合并，符合截图的49秒，但不能把49秒全部称为模型推理。
这里“父请求处理”包含上游响应等待和输出解析，现有持久事件不能进一步精确拆分。

`status`和模型调用耗时事件默认不持久化（`schema/ai_event.go`），所以数据库中没有
这些事件不代表当时未发送。截图中的绿色子卡也不能代替后台manager终态证据。

## 对齐已有事件规范的修复

参考已合入历史的`2e998064c`（enrich user-facing status events）及`aa75cb686`
（migrate user status events to i18n），以及`docs/ai-status-events.md`：

1. 派发回执JSON仍交给父模型和Timeline；可见汇报改为“已派发N个子任务，正在后台执行”。
2. 等待发送`subagent.waiting`状态，明确`state=waiting`，不沿用默认running。
3. 新增静态注册的`sub_react_agents_wait`可见流，开始前写等待说明、返回时写状态摘要，
   然后关闭流。它将等待与前后思考分隔开，也可用于历史重放。
4. 检查/取消/等待的摘要分别显示排队、准备、运行、取消中、完成、失败、取消和执行超时，
   不显示协议JSON，也不把取消请求或阶段答案伪装成完成。
5. 观察超时明确写“本次等待已到时，子任务继续执行”。状态事件保留中文value、英文翻译、
   稳定code及真实终态计数；原始错误仅反馈给模型。

默认30秒、最大10分钟及事件驱动提前返回保持原有语义。本次不增加自动取消模型请求、
中途替换模型输入或把父结束后重新唤醒的机制。
