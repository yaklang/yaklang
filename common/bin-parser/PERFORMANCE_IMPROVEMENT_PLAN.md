# 后续性能改进方向

已交付的优化和 2026-09-07 实测统一见 [README](README.md)，协议边界见 [当前范围](ACTIVE_SCOPE.md)。以下是尚未交付的方向：

1. 按链路类型、EtherType、IP 协议号建立分发表，分离探测、消息边界处理、解码和导出。端口只用于候选排序，数据不足与不匹配应区分，限制未知流探测成本。
2. 明确协议后按连接保存解析器、版本和会话阶段，处理升级、关闭、超时与端口复用。按需重组 TCP，限制流数量、重组内存和空闲时长。
3. 用包含传输协议、规范化端点及接口/隧道作用域的双向流键，将同一流交给长期 worker，保持顺序与局部状态；测量热点流和跨 worker 调度成本。
4. 分别测量字节解码、规则建树、配置写入、投影与序列化。保留 YAML / Yak 扩展路径、完整字段、错误、类型、nil、事务和结果所有权语义，用新旧差分验证实际收益。
5. 在受控到达率、有限队列和长期负载下测量丢弃、排队及输出成本，再评估客户端和 aid 集成。离线基准不能替代这些容量与体验测试。
