# 新抓 TLS/QUIC 的来源核验（d677）

本页记录新 Windows 真实流量及 `d6772965c669e288705f7e0d0e25c62972226832`
的独立来源核验。先冻结源包、端点收据、独立解密和流区间，再读取候选输出。
下面的准确数量不是整体 TOP30 覆盖率，也不等同于所有扩展已经正确。

| 范围 | 独立来源与实际 SDK 核验 |
|---|---|
| TLS | 227物理帧、8个真实连接、4次恢复、136条记录、94次AEAD成功、16条认证close_notify |
| HTTP/1.1 | 24对完整请求/响应，逐消息、body摘要、记录父来源、请求关联正确 |
| QUIC | 2018物理帧、2025受保护包，2022认证成功、3个真实坏tag，不给失败包填造PN或明文 |
| 恢复与复用 | 3种cipher、3连接、6次key update、3次CID rotation、3次NAT rebind，180个观察到的乱序包 |
| HTTP/3 | 36个完整HEADERS、36个完整body、81个逻辑frame；2592项应用字节来源区间核验 |

所有18个cipher×方向×epoch单元都独立解密，并有138次变异拒绝控制。六个全零
datagram tail另记为未受保护的填充，不计为受保护包或认证成功。请求事务按原始
stream连续交付推导；526个纯缓冲/重复片段不虚构请求锚。新握手各自重置版本、
cipher、ALPN及恢复上下文，Session ID/PSK/ticket只表达观察到的提议与选择，
不声称验证binder、证书信任或对端身份。

隔离TShark4.6.9的72632个标量/bytes检查没有差异。参考仅导出33/36个完整
`http3.data`视图；另外三个body由独立原始STREAM区间和FIN证明完整，其中两个
在FIN后补洞。所有相应STREAM bytes均与参考一致。该事实只是参考导出范围的
遗漏，没有声称观察到Wireshark内部状态或已证明Wireshark存在bug。

CLI的2245个物理记录全部核对编号、纳秒时间、接口、长度、地址及端口；2220个
native PDU及41694个私有字段occurrence精确桥接，没有重编号或遗漏。这一历史
检查仍保留**两处标签差异**：帧1011/1012已经认证且选中h3，但新双向流开头缺失、
后续仅缓冲时仍显示QUIC。修复及新二进制/页面证明另行记录，本页不把未完成的
展示核验算作通过。

另用实际CLI核验8项字段筛选合同：`http.request.method`指当前PDU新解出的字段
section，纯buffer/重传不重复附上旧HEADERS，否定谓词不能解释成“整个stream没有
POST”。未注册的`http3.request.method`和`http3.request_pdu`明确报错。随后发现的
动态QPACK恢复后method投影遗漏不在这批新流量覆盖内，需单独补测和修复。

保留最初TLS生成器的unwrap/RST竞态失败，以及三个独立checker/格式适配错误。

源码及计数/摘要索引见 [证据索引](tls-quic-fresh-d677-summary.json)，完整源网格、
